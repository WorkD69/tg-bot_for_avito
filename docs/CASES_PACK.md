# Кейсы и примеры работ — Стратегия и шаблоны

## Ключевой принцип: кейс — это доказательство качества, а не слив чужой работы

Правильно оформленный кейс:
- Показывает процесс, а не просто результат
- Не содержит персональных данных клиента
- Обобщает задачу настолько, чтобы её нельзя было атрибутировать конкретному человеку
- Демонстрирует ценность: скорость, качество объяснений, принятие преподавателем

---

## Что ОБЯЗАТЕЛЬНО скрывать

**Персональные данные:**
- Имя, фамилия, ник, аватар клиента
- Номер учебного заведения, группа, курс
- Имя преподавателя
- Конкретный семестр/год (оставляйте только "осенний семестр" без года)

**Уникальные идентификаторы задачи:**
- Номер варианта из конкретного задачника
- Скриншоты с видимым именем преподавателя или учебника
- Любой текст, по которому можно найти задачу в интернете

**Что обобщать:**
- "Курсовая по ТАУ" → "задача по теории автоматического управления"
- "ЛГУ, 3 курс, вариант 17" → "задача университетского уровня"
- "Профессор Иванов не принял" → "преподаватель запросил дополнительные пояснения"

---

## Что ПОКАЗЫВАТЬ

- Тип задачи (математика, физика, программирование)
- Уровень сложности (1–5 баллов или словами: базовая / средняя / высокая)
- Время выполнения (от подтверждения оплаты)
- Формат результата (PDF, скриншоты, исходный код, Word)
- Итог: принято / зачёт / требовались доработки (и были сделаны)

---

## Как обрабатывать реальные работы перед публикацией

**Чеклист для каждого кейса:**

1. Открыть файл решения
2. Убедиться: нет имён, номеров групп, дат, названий учреждений
3. Переформулировать описание задачи — обобщённо, не копируя исходный текст
4. Пересмотреть скриншот/превью: замазать/обрезать всё лишнее
5. Описание результата — только факты: принято / не принято / принято после доработки

**Инструменты для замазывания:**
- Windows: встроенный Paint (заливка области)
- Любой редактор изображений: прямоугольник с заливкой цветом фона
- Простой способ: обрезать скриншот до нужной области

## Шаблон описания кейса (текстовый)

```
Предмет: [Математика / Физика / Программирование / ...]
Тема: [Интегралы / Электрические цепи / Парсинг данных / ...]
Сложность: [Базовая / Средняя / Высокая]
Время выполнения: ~[N] часов

Задача: [1–2 предложения, без персональных данных]

Что сделано:
— [пункт 1]
— [пункт 2]
— [пункт 3]

Результат: [Принято с первой попытки / Принято после правок / Зачёт]
```

## Как использовать кейсы в разных каналах

**Авито (картинки):**
- Формат: карточка 1080×1080px (готовые шаблоны в assets/branding/case_card_0N.svg)
- Публиковать как дополнительные фото к объявлению (слоты 3–5)
- Без конкретных цен на карточке

**Telegram-канал:**
- Текстовый кейс + 1–2 скриншота (замазанные) ИЛИ карточка SVG
- Частота: 1–2 кейса в неделю
- Тэги: #кейс #матанализ #программирование — для поиска по каналу

**В переписке с потенциальным клиентом через Авито:**
- "Вот пример похожей задачи, которую мы выполнили:" + ссылка на пост в канале
- Не присылать сами файлы решений (защита репутации и данных)

## Рекомендации по выбору кейсов для публикации

**Брать в кейс:**
- Задачи с чётким позитивным исходом (принято/зачёт)
- Задачи, где есть интересный процесс (клиент добавил уточнение, оператор уложился в срок)
- Высокочастотные предметы: высшая математика, физика, алгоритмы, SQL

**Не брать:**
- Задачи, где был спор или конфликт (даже разрешённый)
- Задачи, которые были оспорены или переделывались несколько раз
- Очень специфичные задачи, по которым клиент мог бы себя узнать
