# Операционный план запуска — 7 дней

**Режим:** Ручная оплата по реквизитам. Один оператор (ты). Один канал привлечения (Авито). Telegram-канал как доверие.

**Цель:** Получить первые 3–5 оплаченных заявок. Убедиться что продукт продаётся. Не потерять ни одного клиента из-за технических проблем.

---

  - Webhook активен: `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` → `"pending_update_count": 0`
- [ ] Написал боту `/start` с двух разных аккаунтов — работает
- [ ] Проверил что оператор-аккаунт в операторской группе, написал боту `/start` в DM
- [ ] Пройти E2E тест (см. чек-лист ниже) — ОБЯЗАТЕЛЬНО перед выходом

**Брендовый блок:**
- [ ] Установить аватар боту через @BotFather → /mybots → Edit Bot → Edit Botpic → загрузить `bot_avatar.png` (экспортировать из SVG)

  ```

  ```

- [ ] Установить аватар аккаунту @studario_support
- [ ] Убедиться что @studario_support активен и отвечает на тестовое сообщение

**Контентный блок:**
- [ ] Создать Telegram-канал (название: `Studario | Решаем задачи`)
- [ ] Заполнить описание канала (текст в `docs/TG_CHANNEL_PACK.md`)
- [ ] Поставить аватар канала

- [ ] Подготовить текст объявления (в `docs/AVITO_CREATIVE_PACK.md`)

- Бот отвечает на `/start` с любого аккаунта
- Оператор видит новые заявки в группе
- Кнопка "Перейти к заявке" открывает карточку в DM оператора

### Хороший сигнал Дня 0

## ДЕНЬ 1 — Запуск

### Что делаешь руками

**Утро (до 12:00):**
- [ ] Опубликовать объявление на Авито (все 5 фото, полный текст, правильная категория)
- [ ] Проверить что ссылка на бота в описании работает: `t.me/studario_bot?start=avito`
- [ ] Проверить объявление с телефона: фото читаются, текст не обрезан

**После публикации:**
- [ ] Поделиться ссылкой на Telegram-канал в 2–3 своих чатах/группах (попросить подписаться — нужно первых 10–20 подписчиков для соцдоказательства)
- [ ] Опубликовать в канале Пост 2 ("Как работает" или "Почему нам доверяют")

**Весь день:**
- [ ] Быть онлайн или проверять телефон каждые 30–60 минут — Авито даёт пик показов первые 24 часа новым объявлениям

### Что проверяешь каждый час

- Новые сообщения в Авито-чате
- Новые сообщения боту (через операторский аккаунт — видишь все новые заявки в группе)
- Логи: `docker-compose logs --tail=50 bot` — нет ошибок

### Что считаешь хорошим сигналом

- 1–3 обращения в Авито в первый день
- Хотя бы 1 переход по ссылке на бота (видно если клиент написал /start)
- Подписки на канал от незнакомых людей

### Что считаешь плохим сигналом

- 0 обращений за весь день → на День 2 менять заголовок объявления
- Обращения есть, но никто не доходит до бота → проблема в тексте объявления или описании бота

### Что делать при плохом сигнале

**0 обращений за день:**
Поменять заголовок. Проверить категорию объявления. Посмотреть конкурентов — что пишут они.
Варианты заголовков для теста:
```
«Решаю задачи по математике и физике — в Telegram»
«Помогу с задачами: матан, физика, программирование»
«Учебные задачи онлайн — результат в Telegram»
```

**Обращения есть, клиент не создаёт заявку:**
Написать в ответ: "Подскажите, что-то было непонятно в боте? Помогу разобраться" — собрать фидбек вручную.

## ДЕНЬ 2–3 — Первые обращения

### Что делаешь руками

**При каждом обращении через Авито:**
1. Ответить быстро (в идеале до 15 минут)
2. Дать ссылку на бота: `t.me/studario_bot?start=avito`
3. Если клиент спрашивает "сколько стоит?" → "Зависит от задачи — отправьте боту, операторы назовут цену"

**При каждой новой заявке в боте:**
1. Немедленно принять заявку как оператор (в DM бота)
2. Назначить цену — это твоя ставка как оператора
3. Отправить реквизиты клиенту через бот

**При "Я оплатил" от клиента:**
1. Проверить поступление денег
2. Подтвердить оплату командой `/confirmpayment {id}` в DM с ботом (или дождаться от администратора)
3. Приступить к решению — реальная работа

**После решения:**
1. Загрузить файлы через бот (`/done` в оператор DM)
2. Написать клиенту в поддержку: "Всё прошло хорошо? Если остались вопросы — @studario_support"
3. Попросить оставить отзыв прямо в боте

**Контент:**
- День 3: Опубликовать в канале пост-кейс (обезличенный, из первых заявок или синтетический)

### Что проверяешь

- Время между созданием заявки и твоим ответом как оператора (должно быть < 30 минут)
- Конверсия: сколько написали в Авито → сколько создали заявку → сколько оплатили
- Бот не падает, webhook стабилен

### Хороший сигнал

- Хотя бы 1 оплаченная заявка за День 2–3
- Клиент оставил отзыв в боте
- Кто-то написал повторно

### Плохой сигнал

- Клиент дошёл до заявки, но не оплатил → выяснить причину
- Клиент не понял как отправить реквизиты → бот работает некорректно или клиент запутался

### Что делать при плохом сигнале

**Клиент не оплачивает:**
Написать через @studario_support: "Привет, всё ок? Если остались вопросы по задаче или оплате — помогу"
Часто клиент просто передумал — это нормально. Важен паттерн: если 5 из 10 не платят — проблема в цене или объяснении.

**Клиент запутался с реквизитами:**
Значит оператор (ты) недостаточно чётко написал инструкцию. Шаблон для сообщения с реквизитами:
```
Привет! Вот реквизиты для оплаты {сумма} ₽:
Карта: XXXX XXXX XXXX XXXX (Сбер / Тинькофф)
Получатель: [Имя]

После перевода нажмите кнопку «Я оплатил» в боте — начнём сразу.
Вопросы: @studario_support
```

### Что делаешь руками

**Операционный ритм (каждый день):**
- Утром: проверить заявки, сообщения в Авито, новые обращения боту
- Днём: выполнить активные заявки, ответить на вопросы
- Вечером: ежедневный чек-лист контроля бота (см. ниже)

**Контент (один пост каждые 2 дня):**
- День 4: Пост "Часто задаваемые вопросы" или "Какие задачи НЕ берём" (честность повышает доверие)
- День 6: Пост "Кейс недели" — первый реальный обезличенный кейс

**Обновление Авито:**
- Если уже есть реальные отзывы — заменить шаблонный avito_05.svg, обновить 5-е фото в объявлении
- Ответить на все вопросы в Авито-чате (поднимает объявление в поиске)

**После каждой выполненной заявки:**
- [ ] Попросить отзыв в боте
- [ ] Если клиент с Авито и `avito_profile_url` настроен — бот сам предложит отзыв на Авито
- [ ] Занести в личную таблицу: дата, предмет, сумма, источник, статус отзыва

### Что проверяешь к концу недели

- Сколько заявок создано
- Сколько оплачено
- Сколько выполнено
- Конверсия Авито → заявка (если < 20% → менять текст объявления)
- Конверсия заявка → оплата (если < 50% → проблема с ценой или реквизитами)

### Хороший сигнал недели

- 3–5 оплаченных заявок
- 1–2 отзыва в боте
- Хотя бы 1 повторное обращение от того же клиента или рекомендация

### Плохой сигнал недели

- 0 оплат → критическая проблема: цена? доверие? непонятный процесс? → интервью с теми кто не купил
- Бот падал 2+ раз → VPS нестабилен → смотреть логи, проверить RAM

## ЧЕК-ЛИСТ 1: E2E тест перед запуском

Проводить с двух аккаунтов: Аккаунт A = клиент, Аккаунт B = оператор (в операторской группе).

### Блок 1: Регистрация и старт

- [ ] Аккаунт A: написать `/start` боту → приветствие, клавиатура клиента
- [ ] Аккаунт A: нажать "Как это работает" → информационное сообщение, упоминание @studario_support
- [ ] Аккаунт A: нажать "Создать заявку"

### Блок 2: Создание заявки (4 шага)

- [ ] Шаг 1 — Файлы: отправить 1 фото → "Файл принят (1/10)"
- [ ] Шаг 1 — Файлы: отправить документ → "Файл принят (2/10)"
- [ ] Шаг 1 — Файлы: отправить `/done` → переход к комментарию
- [ ] Шаг 2 — Комментарий: отправить текст → принято, переход к дедлайну
- [ ] Шаг 2 — Комментарий: проверить «-» → принято как "нет комментария"
- [ ] Шаг 3 — Дедлайн: отправить прошедшую дату → ошибка "дата уже прошла"
- [ ] Шаг 3 — Дедлайн: отправить "абвг" → ошибка формата
- [ ] Шаг 3 — Дедлайн: отправить корректную дату (через неделю) → принято
- [ ] Шаг 4 — Бюджет: отправить "abc" → ошибка
- [ ] Шаг 4 — Бюджет: отправить "1500" → заявка создана
- [ ] Подтверждение заявки: сообщение "🎉 Заявка принята!" — нет упоминания "2 часов"

### Блок 3: Оператор видит заявку

- [ ] Аккаунт B (операторская группа): новое уведомление о заявке в группе
- [ ] Кнопка "Перейти к заявке" → карточка заявки в DM оператора
- [ ] Карточка содержит: бюджет, дедлайн, статус "В ожидании"

### Блок 4: Ставка и назначение

- [ ] Оператор: нажать "Могу взять" → запрос суммы
- [ ] Оператор: ввести сумму равную бюджету → auto-assign (без ожидания аукциона)
- [ ] Аккаунт A (клиент): уведомление "Оператор принял заявку"

### Блок 5: Ручная оплата по реквизитам

- [ ] Оператор: отправить реквизиты клиенту через DM бота
- [ ] Аккаунт A: уведомление с реквизитами получено
- [ ] Аккаунт A: нажать "Я оплатил" → подтверждение "Мы уведомили администратора", упоминание @studario_support
- [ ] Администратор (ты): получил уведомление об оплате

### Блок 6: Подтверждение и выполнение

- [ ] Ввести `/confirmpayment {id}` → заявка переходит в in_progress
- [ ] Аккаунт A: уведомление что оплата подтверждена, оператор работает
- [ ] Оператор: загрузить файл решения → `/done`
- [ ] Аккаунт A: уведомление о готовом решении, файлы доступны

### Блок 7: Отзыв

- [ ] Аккаунт A: нажать "⭐ Оставить отзыв" → выбор рейтинга
- [ ] Выбрать 5 звёзд → запрос текста
- [ ] Написать отзыв → "Спасибо за обратную связь!"
- [ ] Администратор: уведомление о новом отзыве с кнопками Одобрить/Отклонить
- [ ] Одобрить отзыв → он появляется в "Отзывы о нас"

### Блок 8: Просмотр истории

- [ ] Аккаунт A: нажать "История заявок" → заявка есть в списке
- [ ] Нажать на заявку → карточка с итоговой суммой, датой выполнения

### Блок 9: Edge cases

- [ ] `/cancel` во время FSM → состояние сбрасывается, клавиатура возвращается
- [ ] Нажать "Текущие заявки" когда нет активных → "📭 У вас нет активных заявок"
- [ ] Написать боту произвольный текст вне FSM → бот не ломается (нет 500)
- [ ] Нажать "🔄 Обновить" на карточке → карточка обновляется in-place

## ЧЕК-ЛИСТ 5: Ежедневный контроль бота

Занимает 5 минут. Делать каждое утро.

### Техника

- [ ] `docker-compose logs --tail=100 bot 2>&1 | grep -i error` → нет критических ошибок
- [ ] `docker-compose ps` → все сервисы (bot, db, redis, backup) `Up`
- [ ] Написать боту `/start` → отвечает без задержки
