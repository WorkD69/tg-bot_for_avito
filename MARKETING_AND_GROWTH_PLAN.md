# Marketing & Growth Plan

Операционный документ для запуска трафика и измерения результатов.

## Быстрый старт: как запустить первую кампанию за 15 минут

1. Выбери источник (Авито, Telegram-канал, прямая ссылка)
2. Придумай ID кампании: `ad1`, `june_post`, `manual_chat` — без пробелов, латиница
3. Сгенерируй deeplink по схеме ниже
4. Размести ссылку в объявлении
5. Через несколько дней смотри `/sourcefunnel` и `/campaignstats avito`

---

## Deeplink-формат

Все deeplink строятся по одному шаблону:

```
t.me/ВАШ_БОТ?start={source}_{campaign}
```

Примеры:

| Ссылка | source | campaign |
|---|---|---|
| `?start=avito_ad1` | avito | ad1 |
| `?start=avito_ad2` | avito | ad2 |
| `?start=avito_summer` | avito | summer |
| `?start=tg_channel_post1` | tg_channel | post1 |
| `?start=tg_channel_june` | tg_channel | june |
| `?start=direct_manual1` | direct | manual1 |
| `?start=avito` | avito | (без кампании) |
| `?start=tg_channel` | tg_channel | (без кампании) |
| Без параметра `/start` | unknown | — |

### Правила именования campaign

- Только латиница, цифры, дефис
- Без пробелов и спецсимволов (кроме `_`)
- Смысловое: `ad1`, `post_june`, `manual_vk` — не `123`, не `test`
- Если неизвестный payload (`?start=mylink`) — сохранится как `source=direct, campaign=mylink`

### Готовые ссылки (скопируй и вставь)

**Авито:**
```
https://t.me/ВАШ_БОТ?start=avito_ad1
https://t.me/ВАШ_БОТ?start=avito_ad2
https://t.me/ВАШ_БОТ?start=avito_ad3
```

**Telegram-канал:**
```
https://t.me/ВАШ_БОТ?start=tg_channel_post1
https://t.me/ВАШ_БОТ?start=tg_channel_post2
```

**Прямые / ручные:**
```
https://t.me/ВАШ_БОТ?start=direct_manual1
https://t.me/ВАШ_БОТ?start=direct_chat1
```

## Аналитические команды

### `/sourcestats [period]`
Только количество зарегистрированных пользователей по источнику. Показывает кто зашёл — не кто заплатил.

```
/sourcestats
/sourcestats 7d
/sourcestats 30d
/sourcestats today
```

### `/sourcefunnel [period]`
**Главная команда для оценки качества трафика.**
Показывает воронку для каждого источника: регистрации → заявки → оплаты → завершения + выручка.

```
/sourcefunnel
/sourcefunnel 7d
/sourcefunnel 30d
```

Пример вывода:
```
📊 Воронка по источникам (30 дней)

📌 Авито
  👤 Зарег.: 40  →  📋 Заявки: 28 (70%)  →  💳 Оплат: 15 (53.6%)  →  ✅ Завершено: 12 (80%)
  💰 Выручка: 60 000 ₽   🎯 Completion: 42.9%

📌 Telegram-канал
  👤 Зарег.: 12  →  📋 Заявки: 9 (75%)  →  💳 Оплат: 6 (66.7%)  →  ✅ Завершено: 5 (83.3%)
  💰 Выручка: 25 000 ₽   🎯 Completion: 55.6%
```

### `/campaignstats [source] [period]`
Воронка с разбивкой по конкретным кампаниям. Позволяет сравнивать объявления между собой.

```
/campaignstats                    — все источники, всё время
/campaignstats avito              — только avito кампании, всё время
/campaignstats avito 7d           — avito, последние 7 дней
/campaignstats tg_channel 30d     — tg_channel, последние 30 дней
/campaignstats 7d                 — все источники, последние 7 дней
```

Пример вывода:
```
📊 Кампании / Авито (7 дней)

📌 Авито / ad1
  👤 Зарег.: 20  →  📋 Заявки: 15 (75%)  →  💳 Оплат: 8 (53.3%)  →  ✅ Завершено: 6 (75%)
  💰 Выручка: 30 000 ₽   🎯 Completion: 30%

📌 Авито / ad2
  👤 Зарег.: 8  →  📋 Заявки: 4 (50%)  →  💳 Оплат: 1 (25%)  →  ✅ Завершено: 1 (100%)
  💰 Выручка: 5 000 ₽   🎯 Completion: 12.5%
```

→ Видно: `ad1` даёт больше трафика и конвертирует лучше → масштабируй `ad1`.

## Как сравнивать кампании

### Ключевые метрики (в порядке важности)

| Метрика | Как читать |
|---|---|
| **Completion rate** | Заявки → Завершено. Главный показатель качества |
| **Paid / Orders rate** | Конверсия в оплату. Если низкая — цена слишком высокая или клиенты нецелевые |
| **Gross revenue** | Деньги. Не путай с operator_share |
| **Registrations** | Охват. Много регистраций при нулевых заявках — плохой оффер |

### Чек-лист анализа кампании (через 7–14 дней)

- [ ] `/campaignstats avito 7d` — сравниваю completion rate по объявлениям
- [ ] `/sourcefunnel 7d` — сравниваю источники между собой
- [ ] Если completion rate < 20% — проблема в качестве клиентов или онбординге
- [ ] Если Paid/Orders < 40% — цена слишком высокая или клиент не понимает как платить
- [ ] Лучший campaign → масштабируй бюджет и текст объявления

## P1 — Реализовано: Onboarding + Follow-up

### Welcome по источнику

При **первом** `/start` (новый пользователь) бот показывает текст, адаптированный к источнику:

| source | Текст |
|---|---|
| `avito` | "Нашли нас на Авито — отлично! Нажмите «Создать заявку»..." |
| `tg_channel` | "Рады видеть из нашего канала! Нажмите «Создать заявку»..." |
| `direct` / `unknown` | Нейтральный стандартный текст |

**Повторный `/start`** — всегда нейтральный текст (не спамит). Операторы/администраторы видят свой стандартный экран.

Чтобы добавить новый источник:
1. Добавить строку в `KNOWN_SOURCES` в `app/db/models/user.py`
2. Добавить запись в `_WELCOME_BY_SOURCE` в `app/bot/routers/client/menu.py`

### Follow-up через 24 часа после завершения

**Что происходит:** когда заявка завершается (оператор отправляет `/done` или admin использует `/completeorder`) — бот планирует APScheduler job на `+24 часа`.

**Что отправляется:**
```
👋 Иван, надеемся, задача №42 выполнена отлично!

Если появятся ещё задачи — мы здесь 📋 Просто нажмите «Создать заявку»

Кстати, будем рады вашему отзыву — откройте «История заявок» → заявка №42 → «⭐ Оставить отзыв»
```
(строка про отзыв отсутствует, если клиент уже оставил отзыв)

**Защиты от дублей и спама:**

| Guard | Поведение |
|---|---|
| `orders.followup_sent_at IS NULL` | Атомарный UPDATE — невозможно отправить дважды даже при гонке |
| `status = completed` | Не отправляется по отменённым/активным заявкам |
| Клиент имеет активные заявки | Skip — уже взаимодействует с ботом |
| Ошибка `bot.send_message` | Логируется, `followup_sent_at` уже выставлен → retry не происходит |
| `replace_existing=True` в scheduler | Повторный вызов `schedule_followup_job` не дублирует job |

**Наблюдаемость:** `/stats` показывает `📬 Follow-up отправлено: N заявок` — по этому числу видно, что механика работает.

### Как тестировать руками

1. Создай тестовый заказ, доведи до завершения
2. В БД выполни:
   ```sql
   SELECT id, followup_sent_at FROM orders WHERE id = {id};
   ```
   → `followup_sent_at` должен быть NULL
3. В APScheduler jobstore:
   ```sql
   SELECT id, next_run_time FROM apscheduler_jobs WHERE id = 'followup_{id}';
   ```
   → job должен быть запланирован на завтра
4. Для ускорения теста: обнови `next_run_time` в БД на текущее время и подожди несколько секунд
5. Проверь что сообщение пришло и `followup_sent_at IS NOT NULL` в orders

## Технические детали

### Как хранится attribution

- `users.source` — источник (avito | tg_channel | direct | unknown). Записывается **один раз при регистрации**
- `users.campaign` — кампания (ad1 | post1 | manual1 | NULL). Записывается **один раз при регистрации**
- Изменение source/campaign у существующих пользователей не происходит — повторный `/start` не перезаписывает

### Формат payload (технически)

```
/start avito_ad1
  → payload = "avito_ad1"
  → source = "avito" (known prefix)
  → campaign = "ad1" (остаток после avito_)

/start tg_channel_post1
  → source = "tg_channel"
  → campaign = "post1"

/start unknownlink
  → source = "direct"
  → campaign = "unknownlink"   ← payload сохраняется, данные не теряются

/start
  → source = "unknown"
  → campaign = NULL
```

### Добавление нового источника

Если нужен новый источник (например `vk`):
1. Добавить `"vk"` в `KNOWN_SOURCES` в `app/db/models/user.py`
2. Добавить метку в `SOURCE_LABEL` в `app/bot/routers/admin/analytics.py`
3. Ничего больше менять не нужно — парсинг работает автоматически
