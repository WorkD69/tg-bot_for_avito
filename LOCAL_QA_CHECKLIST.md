# Local QA Checklist

Ручные проверки для локального окружения (ngrok + Docker).
Запускай перед каждым значимым изменением и перед деплоем.

## Подготовка

```bash
docker-compose up -d --build
docker-compose ps            # все сервисы: Up (healthy)
docker-compose logs -f bot   # нет ERROR в первые 10 секунд
```

Ngrok должен быть запущен, `WEBHOOK_BASE_URL` в `.env` — ngrok-URL.

---

## Блок 1: Базовый запуск

- [ ] Отправить `/start` боту -> 4 reply-кнопки
- [ ] Startup logs: нет `ERROR`; есть `INFO` о режиме Robokassa
- [ ] `/health` endpoint: `curl http://localhost:8000/health` -> `{"status": "ok"}`

## Блок 2: Создание заявки (FSM клиента)

- [ ] "Создать заявку" -> бот просит файлы
- [ ] Отправить фото -> подтверждение; `/done` -> бот просит комментарий
- [ ] "-" (пропуск) -> бот просит дедлайн
- [ ] Дата в прошлом -> бот отклоняет
- [ ] Корректная дата -> бот просит бюджет
- [ ] Отрицательное число -> бот отклоняет
- [ ] Корректный бюджет -> заявка создана
- [ ] В группе: "Новая заявка №{id}" + кнопка + reply keyboard

## Блок 3: Оператор — просмотр и ставка

- [ ] "Свободные заявки" в группе -> бот отвечает в личку, не в группу
- [ ] "Перейти к заявке" в группе -> карточка в личке
- [ ] Оператор не писал /start -> алерт "напишите /start боту"
- [ ] "Могу взять" -> вводит сумму -> ставка принята, карточка обновилась
- [ ] Ставка = бюджету -> авто-назначение
- [ ] "Обновить" -> карточка обновляется in-place

## Блок 4: Аукцион

- [ ] `/endauction {id}` -> оператор назначен
- [ ] Без ставок + `/endauction` -> заявка отменена, клиент и admin уведомлены

## Блок 5: Оплата

**Ручной режим:**
- [ ] Клиент видит кнопку "Я оплатил"
- [ ] Нажать -> admin получает уведомление
- [ ] `/confirmpayment {id}` -> статус "В работе", оба уведомлены
- [ ] Повторный `/confirmpayment` -> предупреждение

## Блок 6: Переговоры по цене

- [ ] "Обсудить цену" -> клиент вводит текст -> оператор получает кнопки
- [ ] "Принять" -> клиент уведомлён о новой цене
- [ ] "Встречная сумма" -> "3500 Минимально возможно" -> клиент получает оба
- [ ] Кнопки на старом сообщении (после нового раунда) -> алерт "устарело"
- [ ] "Отменить заявку" -> заявка отменена, клиент и группа уведомлены

## Блок 7: Работа и решение

- [ ] "Написать клиенту" -> клиент получает + "Ответить оператору"
- [ ] Клиент отвечает -> оператор получает
- [ ] "Добавить заметку" -> заметка в карточке
- [ ] "Отправить решение" -> файлы -> `/done` -> заявка завершена
- [ ] Клиент получает уведомление с комментарием оператора

## Блок 8: Файлы

- [ ] "Файлы" -> бот редактирует сообщение (edit), показывает файлы
- [ ] "Назад" -> карточка восстанавливается (edit обратно)
- [ ] "Решение" у клиента -> файлы + кнопка "История заявок"

## Блок 9: Отзывы

- [ ] "Оставить отзыв" -> выбор рейтинга -> текст -> "Спасибо!"
- [ ] Admin одобряет -> отзыв в "Отзывы о нас" (имя без @username)

## Блок 10: Admin команды

- [ ] `/addoperator`, `/deleteoperator`, `/addadmin`, `/removeadmin`
- [ ] `/operators`, `/admins`, `/stats`
- [ ] `/cancelorder {id}` -> клиент и оператор уведомлены
- [ ] `/completeorder {id}` -> только для in_progress
- [ ] `/commands` -> список всех команд

## Блок 11: Граничные случаи

- [ ] 6-я заявка одним клиентом -> отклоняется "превышен лимит"
- [ ] "Написать клиенту" во время загрузки решения -> алерт
- [ ] Рестарт контейнера -> FSM-состояние сохранено (Redis)

## Блок 12: После рестарта

```bash
docker-compose up -d --build bot   # Применяет код + рестартует
```

- [ ] Миграции применены (лог: `alembic upgrade head`)
- [ ] Webhook установлен
- [ ] Аукционный таймер восстановлен
