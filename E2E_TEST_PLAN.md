# E2E Test Plan

Полный сценарий end-to-end с тремя участниками.

## Участники

| Роль | Аккаунт |
|------|---------|
| Клиент | Telegram-аккаунт A |
| Оператор 1 | Telegram-аккаунт B |
| Оператор 2 | Telegram-аккаунт C |
| Администратор | Telegram-аккаунт D (ADMIN_TELEGRAM_ID) |

**Предусловия:** B и C назначены операторами, написали /start боту, состоят в группе.

---

## Фаза 1: Создание заявки

**Клиент (A):** /start -> "Создать заявку" -> фото -> /done -> комментарий -> дедлайн -> бюджет 2000

**Результат:**
- A: "Ваша заявка создана!"
- Группа: "Новая заявка №{id}" + кнопка + reply keyboard
- DB: status=pending, auction_end_at=now+120min

---

## Фаза 2: Ставки операторов

**Оператор B:** "Перейти к заявке" -> "Могу взять" -> 1800
**Оператор C:** "Перейти к заявке" -> "Могу взять" -> 1700

**Проверка DB:**
```sql
SELECT operator_id, amount FROM bids WHERE order_id = {id} ORDER BY amount;
-- C (1700) должен быть первым
```

**Admin D:** `/endauction {id}` -> C назначен (минимальная ставка)

**Результат:**
- C: уведомление о назначении
- A: уведомление + способ оплаты
- B: "Заявка ушла другому оператору"
- DB: operator_id=C.id, status=awaiting_payment

---

## Фаза 3: Переговоры по цене

**Клиент A:** "Обсудить цену" -> "Можете за 1500?"
**Оператор C:** "Встречная сумма" -> "1600 Ниже никак"
**Клиент A:** получает "Оператор предлагает 1600 руб."

**DB:** payment_amount=1600, payment_revision=1

---

## Фаза 4: Оплата (ручной режим)

**Оператор C:** "Отправить реквизиты" -> "Карта Сбер: 1234..."
**Клиент A:** получает реквизиты -> нажимает "Я оплатил"
**Admin D:** получает уведомление -> `/confirmpayment {id}`

**Результат:** status=in_progress, payment_confirmed_at заполнен

---

## Фаза 5: Переписка

**Оператор C:** "Написать клиенту" -> "Уточните условия"
**Клиент A:** "Ответить оператору" -> "Задача в приложении"
**Оператор C:** "Добавить заметку" -> "Задача решена"

---

## Фаза 6: Загрузка решения

**Оператор C:** "Отправить решение" -> файл PDF -> "Решение прикреплено" -> /done

**Результат:**
- C: "Решение загружено, заявка завершена"
- A: "Заявка выполнена! Комментарий: Решение прикреплено"
- DB: status=completed, solution_uploaded_at заполнен

---

## Фаза 7: Просмотр и отзыв

**Клиент A:** "История заявок" -> карточка -> "Решение" -> файл -> "Оставить отзыв" -> 5 звёзд -> текст
**Admin D:** одобряет отзыв
**Проверка:** отзыв в "Отзывы о нас" с full_name, без @username

---

## Таблица изменений состояния

| Событие | status | Поле |
|---------|--------|------|
| Создана | pending | - |
| Оператор назначен | awaiting_payment | operator_id |
| "Я оплатил" | awaiting_payment | payment_received_at |
| /confirmpayment | in_progress | payment_confirmed_at |
| /done оператора | completed | solution_uploaded_at |

---

## Что нельзя проверить без реального сервера

- Robokassa в боевом режиме
- Let's Encrypt SSL через Caddy
- Бэкап в реальной Telegram-группе
- Нагрузочное тестирование аукциона
